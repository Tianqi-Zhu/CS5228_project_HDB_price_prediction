## 实际检查过程

1. 在隔离目录只放入本方法的代码、文档、四份 CSV 及来源元数据，不复制其他模型或 `analysis/`。
2. 使用 Python 3.11.15 创建全新 venv，`include-system-site-packages = false`，
   从官方 PyPI 按 `requirements.txt` 安装五个固定版本的包；`pip check` 通过。
3. 在该环境运行全部 9 项检查，然后生成五份结果 CSV 和参考摘要。
4. 将上述代码、输入数据和说明提交到本地独立分支。
5. 从该分支执行一次全新的本地 Git 克隆，不复制原目录的 `outputs/`、虚拟环境或缓存。
6. 在干净克隆目录中使用刚建立的纯净 venv 再运行全部检查和主脚本。
   运行前明确检查：输出目录不存在、没有 `analysis/`、无法导入 `analysis`，
   NumPy 和 pandas 都来自该纯净 venv，未启用用户级 site-packages。
7. 对比两次运行的四份输入哈希、代码哈希、全部五份输出 CSV 哈希及误差指标。
   这些项目全部一致，克隆目录的 Git 工作区仍然干净；输出文件由 `.gitignore` 忽略。

纯净 venv 只提供声明过的第三方依赖，第二次运行加载的项目代码和四份输入全部来自干净克隆。
每次运行都会重新计算预测，不会读取 `results/summary.json` 作为预测输入。

## 如何查看验证对应的版本

`results/reproduction_check.json` 的 `tested_source_commit` 记录实际干净克隆运行的代码版本。
之后补充的提交只包含这份复现记录、机器可读检查结果和 README 链接，不改变执行代码或输入数据。
`code_sha256` 和四份输入 SHA-256 可进一步核对运行内容；再次运行时，时间戳可能不同。
